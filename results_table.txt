TWO MEASUREMENT QUESTIONS STILL OPEN
====================================

Both affect how a number should be read, not whether it was measured.

1. What the d_nw01 capacity figure counts. The checker's own
comment predicts the reference reaching MAX_TRANS + 1 = 9 at
MAX_TRANS = 8. It measures 27, consistently, across every geometry —
while at MAX_TRANS = 2 it measures exactly 3, which is MAX_TRANS + 1.
The relation holds at one depth and not the other. The figures remain
comparable between designs, since every design is measured by the same
harness at the same configuration, but the units are not established
and nothing here should be read as "27 concurrent transactions".

2. Whether the d_ca04 crossing latencies are comparable at all.
Minimum crossing latency scales differently on each design: the
gemini submission tracks the synchroniser depth exactly (2 stages →
2 cycles, 3 → 3), chat tracks depth plus one, and **the reference is
flat at 3 regardless of depth**. Two of those are a plausible design
tradeoff. The third suggests the reference's fastest path may not
traverse the full synchroniser chain — in which case the metric is
sampling something different on that design and the three numbers are
not a like-for-like comparison. This also decides whether gemini's
2-cycle crossing is a genuine result or an artefact. Unresolved.

VERIFICATION TASK
=================

A different measurement, kept on its own table on purpose. A
verification submission is a testbench, not a design: it is judged by
which implementations it accepts and rejects, and there is no area or
frequency to report. Putting it in the grid above would invite averaging
two things that do not share units.


V_CA05 — TAG TRACKER (OUT-OF-ORDER QUEUE)
=========================================

The model is given a port map and a written specification. **It never
sees the RTL.** It writes a testbench, which is then run against the
correct implementation and against deliberately faulty ones.

testbench                accepts correct design  accepts legal variants  catches faults                  status
---------------------------------------------------------------------------------------------------------------
our reference testbench                     yes                     4/4             6/6  the ceiling; corrected
chat                                        yes                     4/4             2/6  3 faults hung it — no 
gemini                                       no                       —               —  rejects the correct de

  our reference testbench: the ceiling; corrected after the fault set exposed two gaps in it
  chat: 3 faults hung it — no watchdog — and 1 went undetected
  gemini: rejects the correct design; checks status before applying reset

- accepts correct design — does it pass a known-good implementation?
  A testbench that rejects correct hardware is unusable whatever else it catches.
- accepts legal variants — four implementations that differ from the
  reference only where the specification is deliberately silent. A correct
  testbench must accept all four; failing one means it checked something
  the specification never promised.
- catches faults — six implementations each carrying one deliberate
  defect: capacity, ordering, starvation, boundary conditions, masked search.
  Every one is proven catchable.

Reported per fault, never as a rate. chat's six outcomes are 2
caught, 3 hangs and 1 miss — four different problems, and a single
percentage hides all of them. A hang is not a catch: the testbench did
not detect the fault, it stopped, and a correct-but-slow design would
hang it identically.

The headline result is that this worked at all. chat wrote a
testbench from prose alone that accepts the correct design and all four
legal variants — no reliance on unspecified behaviour. That is the
finding; the fault-catching score is the weaker half.

---

"PPA predates the correctness interlock" — these place-and-route
numbers were produced before the pipeline required a passing
correctness run first. All the designs so marked have since passed
correctness, so the numbers stand; the note records that nothing
enforced the ordering at the time they were taken.
