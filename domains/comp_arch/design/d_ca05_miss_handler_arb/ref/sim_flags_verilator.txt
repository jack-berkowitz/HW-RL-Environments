# the repository root. Blank lines and lines starting with # are ignored.
#
# TWO GROUPS, and they are there for different reasons.
#
# 1. THE TASK'S OWN PACKAGE, spec/miss_handler_arb_pkg.sv. It is part of the task
#    TEXT -- a submission imports it and the contract is written in its types --
#    so it must be compiled before the candidate. d_nw01 does the same with
#    axi4_xbar_pkg.sv, and task_text_hash covers all of spec/, so the package is
#    hashed with the interface.
#
# 2. THE VENDORED CVA6 CLOSURE, needed only by the REFERENCE. A submission needs
#    none of it: miss_handler_arb is written entirely in the task package's
#    types. But sim_candidate.sh uses one flag file for both, so the closure is
#    listed here and a candidate simply does not reference it.
#
# ORDER MATTERS: packages before the modules that import them, and slang does not
# search library directories the way Verilator's -y does.
#
# ONLY cv64a6_imafdc_sv39_config_pkg.sv may be listed. Every CVA6 config file
# declares `package cva6_config_pkg`, so naming two is a duplicate-package error
# and naming the wrong one silently builds a different machine.
