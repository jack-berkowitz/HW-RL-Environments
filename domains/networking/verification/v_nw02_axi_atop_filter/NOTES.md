# v_nw02 `atop_filter` — build notes

Tier-B. Anchor: PULP `axi/src/axi_atop_filter.sv` at
`4da15979747f326bde2f9869c64e587ce599772c`, SHL-0.51.

## Why this design

A testbench cannot check it by comparing inputs to outputs, because the
interesting outputs **do not correspond to any input**. The unit blocks a
transaction and then manufactures the replies that the blocked transaction
would have produced, while ordinary traffic keeps flowing around it. To check
that, a testbench has to model which writes are filtered, what each one owes on
B and on R, which W beats may reach the master port, and the downstream write
debt. Nine of the sixteen behavioural clauses need that model.

## Step 1 — semantic confirmation (measured, not read)

Confirmed on the anchor before any spec text was written:

| question | measured |
|---|---|
| is a non-atomic write forwarded? | yes, 1 AW and 1 W beat downstream |
| is an atomic write blocked? | yes — master AW count unchanged |
| what replaces it? | one B with `resp=10` (SLVERR) |
| and for `atop[5]` set? | `awlen+1` R beats, each SLVERR — measured 4 for `awlen=3` |
| is `atop` ever seen downstream? | 0 of 1 forwarded AWs carried a non-zero atop |
| are the absorbed W beats forwarded? | no — master W count counts only the forwarded write |

### The bound, and the trap in it

`AxiMaxWriteTxns` is exact at 4: offering AW continuously with **no W beats and
no B responses**, exactly 4 were admitted and `awready` dropped the cycle the
counter reached 4.

The counter increments on a downstream **AW** handshake and decrements on a
downstream **W-last** handshake. It is *not* a count of writes awaiting a
response. Completing one W burst freed exactly one slot while zero B responses
had been returned. This is clause **W4**, and it is the clause `af_m2` attacks:
a subordinate that answers promptly makes the two events coincide, so a
testbench whose downstream model returns B immediately cannot tell the
difference. The reference testbench's responder therefore holds every B for 20
cycles after its AW.

## Step 5c — the policy-divergent perturbation

**The named latitude clause is L1: the order of the manufactured B against the
manufactured R beats.** AXI orders the B and R channels independently, and so
does this contract.

Measured on the golden, with both sinks always ready:

- R beats at cycles **5–8**, B at cycle **12** — the golden emits **R first**.
- With the R sink stalled, the B still completed (cycle 51) before any R beat.
- With the B sink stalled, R beats still flowed (93–96) and the B came at 120.

Neither channel is gated on the other, so the ordering is a free choice.

`conformant/conformant_perturbations.sv` (`af_c1_b_before_r`) is an
**independent implementation**, not a wrapper — it does not instantiate the
golden — and it takes the opposite choice: the B is emitted first and every R
beat is held until the B has been accepted. It also diverges on **L2**, driving
a non-zero pattern on `rdata`/`ruser`/`buser` of a manufactured response where
the golden drives zero.

Results:

- **The reference testbench passes it**, so the testbench is checking the
  contract rather than the golden's implementation.
- **No mutant is killed by the policy difference.** All eight defects were
  re-derived on top of the divergent implementation
  (`mutants/policy/`, generated by the same generator) and re-run:
  every one is caught on **both** bases, and the clean divergent implementation
  still passes. `mutants/check_policy_independence.sh` reruns this.

The same artefact is also wired as the second DUT (`dut2/atop_filter_alt.sv`),
generated from it so the two cannot drift. One artefact, two roles, said plainly
rather than counted twice as independent evidence.

## Step 5 — negative controls

**(b) known-bad DUTs: caught, by name.** `negctl/stuck_dut.sv` (all 45 outputs
tied low, generated from the port map so none can be omitted by hand) and
`negctl/reset_polarity_dut.sv` (`rst_ni` treated as active high).

Both were **initially caught only by the simulation watchdog**, with the
reset-polarity DUT reporting *zero* violations before it hung. The cause was in
the reference testbench: `send_w` and `issue_ar` waited for `ready` in unbounded
loops, so a design that never accepts a beat produced a hang, and a hang
diagnoses nothing. Both waits are now bounded and clause X4 was widened to cover
forward progress in both directions. The two controls now report
`FAIL X4: a W beat was offered for 64 cycles and never accepted` and
`FAIL W3/X4: AW id=1 was never accepted`.

**(a) null testbench: NOT rejected — see the harness finding below.**

## Rule 4 — the coverage floor defect, again

The first version of the reference testbench floored on `peak_debt` and on the
number of AWs reaching the master port. Both count **DUT responses**, so a
faulty design can suppress the very coverage that would convict it: the floor
fires, the clause does not, and the defect is misattributed. Every floor now
counts **stimulus** — writes issued by class, multi-beat atomic writes, W beats
sent, and flags for backpressure, reset and filling the bound. The test that
caught it: *can the DUT influence this counter at all?*

## HARNESS FINDING — the null control is not rejected

`negctl/null_tb.sv` declares `atop_filter_tb`, drives nothing, observes nothing,
**never instantiates the DUT at all**, and prints `RESULT: PASS`.

`scripts/sim_verification.sh` reports it as:

```
=> VALID, with gaps in fault detection. NOT a rejection: this
   testbench accepts correct hardware and every legal variant.
   Caught 0 of 8 faults against a ceiling of 8.
```

and the footer counts it: `2 of 2 submission(s) passed the validity gate.`

The harness **does** discriminate — 0 of 8 against the reference's 8 of 8, with
every missed mutant named — so its measurement is sound and this is not a
scoring error. Two things are nevertheless worth fixing, and neither is in this
task's boundary (`scripts/` is owned elsewhere):

1. **The validity gate is satisfied vacuously.** Nothing checks that a
   submission instantiates the DUT. An empty module clears the gate.
2. **The footer reads as a pass.** A reader who stops at
   "2 of 2 submission(s) passed the validity gate" has been told that a
   do-nothing submission passed.

Tier-B step 5 requires the null control to be *rejected*. It is not. Reported
rather than worked around.
